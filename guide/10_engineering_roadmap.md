# 10 从PPO基线到工程部署

本页是设计约束与候选研究路线，不是已实现功能清单，也不锁定某个未来算法。当前实现边界见 [00](00_project_overview.md)，真实资源限制见 [资产审计](../docs/archive_analysis.md)。

## 阶段与进入条件

```mermaid
flowchart LR
    A[当前：闭环可运行] --> B[阶段一：可重复平地行走基线]
    B --> C[阶段二：课程与域随机化、独立地形测试]
    C --> D[阶段三：按证据选择历史、循环、RMA或CPG]
    D --> E[阶段四：实机辨识、部署与分级验证]
```

实机参数辨识和观测可获得性可提前研究，不必等阶段三完成；每个阶段是否推进应由证据决定。

| 阶段 | 应交付的证据 | 尚缺工作/下一阶段门槛 |
|---|---|---|
| 一：基础PPO | 多种子、固定评估集下前进优于零动作；姿态、失败和负载可解释 | 基线评估、有效行走；随后才研究命令跟踪、转弯/变速 |
| 二：鲁棒与地形泛化 | 独立场景成功率、失效分布、课程/随机化消融 | 地形构建、合理接触、随机参数范围和测试隔离 |
| 三：自适应/结构化控制 | 同预算前馈对照、环境变化后的恢复指标 | 序列数据、记忆边界、部署观测一致性 |
| 四：真实部署 | 时序、动作限制、故障处理、负载与连续运行证据 | 状态估计、执行器辨识、实时接口、独立安全层及实机授权 |

这些门槛是建议的实验规则，应在实验前结合机器人能力定义数值，不在资料缺失时编造成功阈值。

## 复杂地形与泛化

当前只有同一平面和固定动力学，初态小扰动不覆盖摩擦、质量或障碍变化。观察到同平面新seed成功不能证明未知地形泛化。

Domain Randomization是在有依据的范围内改变摩擦、质量/质心、执行器响应、延迟或噪声，增加策略对模型误差的容忍。先做辨识或合理敏感性实验确定范围；一开始过宽、相互矛盾的随机化可能让任务不可学。记录每回合参数及随机化采样seed，先单因素再组合。系统辨识、执行器模型、延迟及随机化在真实迁移中各有作用，参见 [Tan等的原始研究](https://arxiv.org/abs/1804.10332)。

Curriculum Learning逐步提高任务难度。可从轻微摩擦变化/小扰动到斜坡，再到起伏/障碍；推进应依据预先定义的完成率和稳定性，并保留简单场景回归，而非只随时间增难。训练地形、验证地形、最终测试地形要分别管理，隔离高度图seed、障碍排列及参数组合；不能反复查看测试失败后把同一场景加入训练仍称其未知。

建议先以同一套PPO做地形/课程消融，再决定是否换算法。需要解决几何、接触、可达性、奖励和观测；算法名本身不会补齐这些信息。复杂地形研究参考 [Lee等的项目与论文](https://leggedrobotics.github.io/rl-blindloco/)，其四足成果不是本六足项目的验证结果。

当前扩展入口为SimRobot模型构建/Env.reset，但地形生成器、参数随机化钩子和课程管理器均未实现。新增时先用独立候选模型与小实验，不先搭大框架。契约目前按固定资产/配置记录，随机化规格与实例记录方式需单独设计。

## 部分可观测性与自适应

当前MLP只看当前本体状态和一份上一动作。未知摩擦、负载、地形前方情况通常不能由一帧唯一确定；站姿时两个不同地面可能产生几乎相同观测。

| 候选 | 核心直觉 | 额外成本与验证 |
|---|---|---|
| 历史堆叠 | 从多帧状态/动作推断运动响应 | 时间对齐、窗口长度、reset清空、输入维度与推理延迟 |
| Recurrent PPO | 隐状态整合时序信息 | 循环策略/序列buffer、episode记忆重置；当前SB3普通PPO不是循环PPO |
| RMA | 训练时利用环境信息形成隐变量，部署时从历史估计它 | 特权信息设计、随机化、适应模块训练、真实历史数据可获得性 |
| CPG+RL | 用振荡器提供节律，策略调节参数或残差 | 六腿相位/耦合、动作映射、控制限制；结构先验也可能限制策略 |

[RMA原论文](https://arxiv.org/abs/2107.04034)提出基础策略与适应模块组合。对本项目的候选设计是先验证历史信息能否识别关键动力学变化，再考虑这种分阶段训练；这部分是工程推断，不代表现有代码实现RMA。

[CPG-RL原论文](https://arxiv.org/abs/2211.00458)研究用强化学习调制耦合振荡器参数。迁移到六足需要重新验证节律、动作空间与接触，不可直接照搬四足配置。

记忆不能凭空看到远处障碍；需要提前规划落足时仍可能要外部感知。先用对照证明失效源于信息缺失或时序需求，再选择方法。

## Sim-to-Real前必须补齐的接口

| 当前仿真便利 | 实机差距与必须验证的内容 |
|---|---|
| MuJoCo直接读机身速度/方向 | IMU、编码器与状态估计器；坐标、滤波、时间戳、延迟和漂移 |
| 理想即时力矩执行 | 实机到底接位置/速度/力矩命令，底层增益、减速器、死区、饱和、温升、电压与力矩速度曲线 |
| 固定质量/惯量/摩擦 | 质量、质心、惯性、接触、足端材料及负载辨识；当前模型参数未标定 |
| 简化box/capsule与地面碰撞 | lm_coxa几何问题、腿间自碰撞缺失、真实足端接触与软硬度 |
| 500Hz PD、50Hz策略的确定性仿真时钟 | 设备实际可达频率、抖动、丢包、动作保持与观测过期处理 |
| 直接reset到stand | 上电、使能、缓慢起立、故障恢复；不能瞬间重置真实姿态 |
| 配置限位和±7 N·m | 已确认的真实关节零位/方向、位置速度加速度/负载边界和独立急停 |

RobotInterface只是Protocol，Env直接创建SimRobot，不能插入RealRobot就认为训练入口适合实机。未来独立部署进程只负责已冻结策略的观测/动作转换，训练与硬件控制保持独立；物理急停、通信看门狗、姿态/负载保护及回退控制不能依赖策略自己学会。

建议实机验证顺序：离线数据/接口一致性 → 硬件在环或不使能推理时序检查 → 受支撑、低幅单关节和站姿验证 → 有保护的短时平地低速 → 重复性和长时负载 → 逐步引入变化。每步事先定义中止条件、人工接管与记录，失败先定位，不用放宽保护换取完成率。当前不执行任何实机步骤。

## 工程指标：定义、可用数据与缺口

| 指标 | 建议定义 | 当前支持情况 |
|---|---|---|
| 行走成功率 | 在规定场景/时长达到预定进展且无失败的回合比例 | play有位移/时长/原因，无自动成功判据 |
| 速度跟踪误差 | 目标与实测速度差的RMSE及偏置 | 无速度命令，当前不能计算有效跟踪成绩 |
| 姿态稳定 | upright最低值、倾斜统计、角速度RMS | Env有状态；play未保存完整轨迹，训练只有均值 |
| 能耗/负载 | 电能或机械功、RMS/峰值/饱和占比、温升 | 有指令机械功代理和峰值，缺真实电流/热/电压模型 |
| 扰动恢复 | 规定扰动后恢复到容差的时间及失败率 | 无扰动协议/生成机制 |
| 未知地形通过 | 按独立场景分层报告成功/失败及完成距离 | 无地形生成或独立测试集 |
| 推理与控制时序 | 延迟p50/p95/p99、最坏值、超期次数、CPU/内存 | play只为显示节奏计时，无独立性能报告 |
| 长期可靠性 | 连续运行时长、故障/接管次数、性能漂移 | 仅短测试，未做真实长时验证 |

训练回报只是其中一项内部信号。每阶段保留对照与失效分布，确认新方法改善了预先登记的工程指标，再扩大范围。
