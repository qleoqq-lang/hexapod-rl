## 3. 代码整理决策与兼容性

本次未改Python、MJCF、mesh、robot/train配置、测试或依赖版本，原有checkpoint保留。通过内容哈希比较确认原有运行相关文件未变，当前机器人contract仍匹配历史验证与模型。这样避免源码字节哈希变化引起无意义的checkpoint不兼容。

低风险整理是扩充.gitignore：环境、缓存、日志、checkpoint、权重、zip、构建与本机配置不入源码仓库。没有删除本地文件；Git忽略规则也不会取消已跟踪文件，发布前仍须审阅暂存清单。

已审查但保留：

- 原dual_side_mujoco_driver.py：虽与SimRobot有部分映射/控制重复，但它是兼容接口，还依赖外部_original_ruckig与电机XML；当前RL不导入，不把它误删为死代码。
- create_rl_mjcf.py及第二份XML：用于模型来源/候选碰撞研究；生成器默认覆盖风险已在文档标出，没有执行。
- linux_smoke_test.sh和requirements-linux.txt：保留历史入口；主安装使用根requirements，旧依赖未完整覆盖当前入口所需环境，不标为已验证安装方案。
- scripts/train.py导入ROOT：虽局部未引用，但导入_bootstrap的副作用负责搜索路径，不能按表面“未用变量”直接删导入。
- RobotInterface、close与smoke_test：小且有当前或后续诊断用途；不为减少行数破坏接口。

当前没有已确认且值得冒兼容性风险删除的运行函数，故不制造代码改动。模块边界足够支撑当前最小闭环；未来地形/随机化入口可在模型创建和reset附近按需扩展，尚不需要后端注册器、大型配置系统或另一套RL框架。

## 5. 潜在问题与待研究修改（本次不实施）

| 项目 | 影响 | 后续应怎样验证 |
|---|---|---|
| 静止策略与无命令任务 | 现有短训尚未前进，forward cap不是速度跟踪 | 先同种子零动作对照，再增加预算与分项诊断 |
| 模型/接触未标定、无腿间自碰撞 | 仿真可能容许实机不可接受动作 | 独立候选模型/几何审计与响应对照；重验并重新训练 |
| 原点位移与质心速度参考点不同 | 精确积分比较存在定义差别 | 指标统一参考点并记录定义 |
| 有限性检查的范围 | 无穷Box不直接拦Inf；所有train标量NaN均被中止 | 区分obs检查、物理检查与解释方差诊断NaN；设计定向测试后决定 |
| 契约粒度较严格但非全版本 | 注释/换行也拒绝旧模型；train源码/依赖不入契约 | 单独设计语义版本与完整实验版本，不直接绕过检查 |
| 配置快照未覆盖有效恢复参数 | 学习率等可能被误判 | 记录有效模型属性、命令、代码版本和种子，先用模板补齐 |
| 无自动独立评估/基线/指标轨迹 | 训练均值可能掩盖失败或reward投机 | 最小零动作/策略比较及逐回合失败统计；独立于训练实现 |
| 默认报告路径固定、输出覆盖 | 自定义报告未被训练读取或旧结果混用 | 明确命令路径；变更行为前先设计报告版本/路径测试 |
| 检查以assert为主 | -O会移除部分断言 | 教学验证不加-O；若作为生产门再研究显式异常 |
| 中断仅有周期模型 | 无现场/rollout精确恢复、无完整失败摘要 | 记录恢复局限，后续按需求增加中断产物协议 |
